# 玩家与内容工作台手册

## 玩家

1. 首页选择已开放的软件测试职境。系统创建服务端游客身份，并冻结本局内容、美术与组局版本。
2. 阅读人物对白，选择实际行动；不懂时读材料卡或问同事。自由输入默认是对话，只有经规则确认的行动才改变进展。
3. 通过“发给”切换工作群或单人私聊；其他NPC不会看到你的私聊和私人手账。
4. 页面显示“已保存”才代表确认。断线时保留输入；用“查询保存结果”或原编号重试恢复。若原操作确定未提交，可以同步后重新选择。
5. 从历史记录另开路线，原路线仍保存；在“路线与存档”切换。下班不会产生低分，手账可以留空。
6. 注册时需要明确勾选认领当前游客旅程。保存一次性恢复码；忘记密码用未使用的码恢复。账号页可以导出、导入自己的存档副本或删除关联数据。
7. 在“我的旅程”点“回顾走过的结局”，或从终局进入回顾页。这里只展示本人实际提交的结局；未走到的故事不显示名称。点击“回看这条路线”打开原分支，另开路线不会清掉原结局。详见[结局回顾](endings.md)。

游客身份依赖当前浏览器Cookie，清除Cookie可能失去游客存档访问权；需要长期保留时请认领或导出。导入不会获取原账号身份与管理员权限。恢复码丢失且忘记密码时，没有免验证找回入口。

## 内容工作台

先在网页注册正式账号，由实例服务器操作者执行bootstrap-admin授予三个独立内容角色，再进入 `/admin`。正式环境应通过管理网络限制访问，MFA仍列入后续计划。

编辑者复制发布包为草稿，通过“节点视图”选择已有节点，编辑标题、背景、对白、解释与选项去向，点“应用本节点修改”后再“保存草稿”。节点图提示结构问题，并在切换节点、版本或离开页面前保护未保存修改。“高级 JSON”可继续编辑Profile、角色、项目、来源、事件与完整结构；两种视图共享同一份本地草稿，保存必须通过严格schema。详见[节点编辑说明](studio-editor.md)。

自动检查验证逻辑引用与剧情图可达性；实际资源文件、许可、审核状态与哈希由发布门禁核验，字段检查通过不等于可以发布。审核者留下具体理由，标明实际审核者类型；合成demo可以保持行业核验pending。管理员发布新版本，或将新局入口回退到已发布旧版。上述状态变化都有审计，旧存档继续使用原来的冻结版本。

生产资源必须有实际文件、哈希、许可与审核记录，缺失不会放行。禁止将任意脚本、SQL、环境变量或密钥放进内容JSON。后台只显示必要运营数量与元审计，不能读取学生私聊或手账。

工作台的批次工具支持预算预估、创建计划、生成候选、按预算续跑与查看逐项校验结果；按seed预览可以检查当前选中版本的映射与行动，不创建玩家存档。当前批次只支持mock，费用为0；真实模型批生成尚未接通，后续需要明确预算、服务端实现与配置。不要把mock候选记录写成真实模型产出或行业专家审核。详细CLI与门禁见[内容库说明](content-library.md)，已执行的浏览器与自动检查见[验收记录](verification.md)。
