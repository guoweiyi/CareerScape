# 个人归档导出与恢复

账号空间提供 JSON 导出与导入。纯旧故事使用 `schemaVersion: "1.1"`，含 AI 职业故事使用 `"1.2"`，包含本人会话、分支、冻结实例、实际事件文本、快照、私人手账与反馈；不包含密码哈希、会话 Cookie、角色权限、模型凭据或动作回执。

导入入口为 `POST /api/account/import`，走与其他写请求相同的身份、Origin 与 CSRF 检查。`ArchiveService` 位于 `apps/web/server/services/archive.ts`，严格契约与关系校验位于 `packages/contracts/archive.ts`。网页和服务端导入上限均为 **16 MiB**（UTF-8字节）。账号导出可包含两种模式；总归档过大时，从“我的旅程”逐局导出。新模式冻结人物资料，并使用保存的生成结果与规则回放，详见 [AI职业故事](galgame.md)。

恢复执行以下检查，全部通过后在单个 SQLite 事务中写入：

1. 格式、大小、严格字段与 SHA-256；未知版本、权限字段和不完整文件拒绝。
2. 冻结包版本、包校验和、资源版本和真实资源文件；缺旧版本时拒绝继续，保留原文件，不偷偷套用新包。
3. 会话、分支、实例、消息来源、回溯点、频道和收件人引用；禁止循环、跨会话引用和未来事件来源。
4. 以固定 seed 和版本复算组局，核对真实模板映射。开局曾回退的实例还必须匹配固定安全包正文、`fixed-safe-v1` seed 与开局回退记录；不能把回退标记用于绕过组局校验。
5. 用保存的实际动作逐步回放规则，检查 revision、效果、每一步状态、最终状态与快照；模型文本不会写入权威效果。

恢复在**当前登录身份**下创建独立副本。服务端生成新的 session、branch、instance、event 和 message ID，并重映射来源引用。原始文件的 owner/actor 是历史数据，不授予权限；游客认领后的旧行为者 ID 也能合法保留为历史来源，再映射为当前身份。账号角色、认证会话、工具权限与旧动作回执从不导入。重复导入完全相同的文件返回先前副本，避免网络重试产生重复数据。

实际文本、私聊收件范围、手账、分支与冻结模板保持一致。恢复不会再次调用模型编造过去对白，也不会把分支后发生的秘密倒灌到共享前缀。归档中可见的建议意图仅用于再次确认，不能直接执行行动。

SHA-256 校验用于识别文件损坏，不是来源签名，也不证明归档文字必然由原模型产生。导入的所有文字继续作为不可信数据，仅以安全纯文本显示，并受 NPC 上下文隔离规则约束。

`tests/archive.test.ts` 覆盖严格导出格式；私聊/手账/分支副本与继续游玩；角色/未知版本/哈希/包版本拒绝；重算哈希仍无法伪造状态；大小和冻结资源缺失；游客认领后的旧行为者；安全包回退分支的恢复与伪造拒绝。实际命令和结果见[验收记录](verification.md)。资源存在性单独由 `checkAssets` 校验，测试通过不等于外部生产环境已验收。
