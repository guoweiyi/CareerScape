# 首包内容库与离线生产

首包 `qa-last-hour@1`《上线前的最后一小时》为原创合成演示。职业范围是小型产品团队中的软件测试新人；栖木工作室、人物、报名项目、材料和工作制度均为虚构。没有借用真实员工身份、内部资料或行业统计。行业审核状态保持 `pending`，智能体结构检查不代表专业审核。

实际内容位于 `packages/content/seed.ts`：1 个职业 Profile、3 张完整角色卡、1 个项目、14 个事件模板、8 个作者节点、3 个结局，以及一个可往返的产品职责短片段。林澄负责复核与协作，周砚负责候选修复，许知负责范围与发布决定。故事无需编程，也不接入真实报名系统；“验证结果”均明确标为模拟材料。

`demoPack` 是冻结的合成发布候选数据。数据库 `packs.status` 与资源门禁决定是否向玩家提供正式开局，不能仅凭 TypeScript 常量中的 `published` 字段绕过后台。资源未通过时数据库保留 `approved`、目录为筹备中；开发者必须显式启用 `DEV_ALLOW_TEXT_PREVIEW=1` 才可文字预览。它不算美术交付完成。实际角色资源使用 `chr_<id>_work_half_<expression>`、`avatar_<id>_neutral` 和 `bg_<scene>_day_wide`，固定 `careerscape-art-v1`。

事件库存覆盖日常、学习、求助、协作、问题排查、认可、顺利完成、边界与交接。每局抽取 6 个阶段的相容模板，不会把 14 个模板全部塞入一局。仅有 3 名具备完整美术的主角色，因此人物组合固定，变化来自相容事件文本；这是首版真实限制。

## 可执行命令

仓库根目录运行：

```sh
pnpm content:plan --dry-run
pnpm content:plan
pnpm content:generate
pnpm content:validate
pnpm content:generate --max-tokens=6000
pnpm content:publish --dry-run
```

命令入口是 `scripts/content/cli.ts`，候选与批次写入实际 SQLite 的 `content_batches`、`templates`。`--batch=<id>` 续跑指定批次；`--variant=<name>` 创建新的配置身份；`--dry-run` 只输出计划、规模、预算、结构/资源门禁和 seed 预览。默认使用明确标识的 `mock-synthetic-v1`，把已写好的原创合成模板复制为候选，**没有调用真实模型，也不代表批量 AI 生成质量已验证**。不会产生付费调用。

每个批次固定职业版本、提示版本、模型标识、配置哈希、单项幂等键、游标、重试次数、token 估算与零费用来源。预算不足在下一项开始前暂停；可明确增加预算后续跑。成功项、审核项与发布项不重生成；失败项最多尝试三次。模板更新仅覆盖 `draft/auto_checked`，不会覆盖已审核记录。

校验包括 Zod 严格字段、职责/事实/行动引用、内容哈希、字符双元组相似度去重；完整包额外验证图、循环、路径、资源逻辑引用、行业审核策略。相似度是候选筛查工具，不等同于人类语义判断。`validate` 不自动批准和发布。

正常发布走后台编辑→自动检查→审核→管理员发布，审核操作、版本和理由记入数据库。CLI 发布只调用同一已鉴权接口：从受保护环境变量 `CONTENT_SESSION_COOKIE` 读取已有管理员会话，获取 CSRF，再请求 `/api/admin/content`；不接受自报角色，不打印凭据。通常直接在后台发布更方便。未通过资源哈希、许可、审核和文件存在性门禁，发布失败。

## 组局与冻结

`assemble(pack, seed)` 使用受约束的确定性抽样，仅选择已发布、职责齐全、前提满足的模板，每阶段只选一个互斥组成员。世界变量和效果通过白名单 DSL 校验；没有 eval、任意脚本或模型直接写状态。冻结字段包括包、数据集、内容 build、Profile、资产 manifest、sampler、seed、人物槽位、项目和实际事件槽映射。

`eligibleEventIds` 在运行时再次筛选角色缺席、前置条件、互斥、已触发和冷却状态。`occurrenceFor` 只读取当前冻结实例中的模板；开局后没有候选就使用当前包的求助、解释和退出，不换包、不重新抽人。

`assembleWithFallback` 只适用于创建实例前：至多一次切换至调用者明确提供的同职业已发布安全包。旧局的状态、实际文本和模板映射不因新版本发布改变。seed 只复现规则抽样，不能复现真实模型文本；实际对白必须保存在事件日志中。

## 审核与缺口

- 已交付：完整合成角色/项目/剧本、14 个候选事件、有限状态可达性检查、预算/续跑/去重管线、数据库持久化 CLI。
- 未冒充完成：行业人工审核、真实模型批生成质量、用户试用反馈、多候选人物池。
- 素材实际完成情况以美术 manifest、资源审核记录与交付日志为准，内容字段不是图片存在的证据。
- P1 扩展：增加不同工作内容的职业包与有美术支持的人物池；通过真实试用和行业审核后，再评估是否需要检索。
