# 图形剧情编辑器使用说明

在 `/admin` 选择一个内容包版本，再使用“节点视图”查看节点及选项去向。图形编辑器与“高级 JSON”共用同一份本地内容包，保存和发布仍使用原有内容工作台接口。当前版本实现已有节点编辑；新建或删除节点、拖拽布局、批量导入和独立子图编辑尚未提供。

## 可编辑的内容

只有 `draft` 草稿可以修改。已检查、已审核、已发布或撤回的版本可以查看；需要修改时先“复制为草稿”。编辑动作需要 editor 角色，审核需要 reviewer，发布或回退需要 admin，三项权限相互独立。

| 字段 | 当前支持 | 边界 |
|---|---|---|
| 节点标题 | 编辑显示标题 | 最多 100 字，不改变节点 ID |
| 场景背景 | 办公室、会议角、软件测试区、露台 | 只能选当前支持的四种背景 |
| 已有对白 | 说话人、表情、正文 | 页面保留已有顺序与数量；每段正文最多 3,000 字 |
| 可选解释 | 编辑解释文字 | 最多 3,000 字 |
| 已有选项 | 标签、说明、目标节点 | 标签最多 140 字、说明最多 300 字；目标必须存在 |

图形操作不修改包身份、版本、节点类型、结局标记、存档点或白名单 DSL 的条件与效果。选项目标改变时，对应作者图边一起更新，原有条件与效果保持不变。若一个选项已有多条边，或选项与边的条件不一致，需要先通过高级 JSON 修复，图形编辑器不会自行重写规则。

背景、对白人物或表情改变时，节点资源引用会同步更新，并将所需立绘、平静表情回退和头像引用加入包的资源清单。角色设定与其他节点保持原样。引用同步只登记依赖，不生成图片，也不证明实际文件可发布。

## 从修改到发布

1. 选择需要修改的已发布版本，点击“复制为草稿”，核对新草稿的包 ID 和版本。
2. 点击图中的节点，或展开“列表视图：逐个查看节点与路径”。填写该节点的标题、对白和选项等字段。
3. 点击“应用本节点修改”。这一步更新页面中的内容包和高级 JSON，还没有写入服务器；“还原本节点未应用修改”可以撤销当前表单的改动。
4. 点击工作台“保存草稿”。保存通过严格字段校验后写入服务器；字段合法但暂时存在循环、未连接节点等问题的草稿可以保存，仍不能据此发布。
5. 阅读图诊断并修复问题，再执行“自动检查”。服务端检查引用、可达性、完整路线和受约束组局。需要按 seed 查看映射时，先应用并保存所有改动，再使用“按 seed 预览组局”。
6. 审核者记录具体审核理由并“审核通过”，管理员再“发布新版本”。正式行业内容仍要求专业审核；原创合成演示保留既有标记，不把自动检查写成人工审核。

节点表单有未应用修改时，工作台会阻止保存、检查、审核和版本操作；内容包有未保存修改时，检查、审核、发布与版本操作会要求先保存。预览读取服务器已保存的版本，因此也会要求先应用并保存。

## 未保存修改与 JSON 互通

页面区分两层修改：节点表单中的“尚未应用”，以及已经进入本地内容包但“尚未保存到服务器”。

- 切换节点时，如果当前表单尚未应用，会出现“丢弃修改并切换”和“继续编辑当前节点”。想保留修改，应继续编辑并先应用。
- 切换图形与高级 JSON 方式时，尚未应用的节点表单会先请求确认；已经应用到本地内容包的修改仍保留。
- 切换内容版本或离开工作台时，存在任一层未保存修改都会请求确认。刷新、关闭页面使用浏览器的离开提示；其显示方式由浏览器控制，不能把提示当作自动保存。
- 同一个节点从其他编辑位置发生改变时，未应用的旧表单会阻止覆盖，要求重新载入。此保护属于当前页面状态检测，不是多人协作锁或跨浏览器合并。

图形修改应用后立即写入同一份本地 JSON；切到高级 JSON 可以检查实际变化。反过来，高级 JSON 通过内容包 schema 后，切回图形即可查看新结构；JSON 无法解析或字段不合法时，图形界面会要求先修复 JSON。

高级 JSON 保留原有白名单规则编辑能力，仍需严格 schema 与服务端检查。不要通过改版本号、状态字段或任意脚本试图绕过服务器权限和发布流程。

## 图诊断与布局

节点按作者图的前后关系自动分层；合流节点考虑各条前驱路径。列表视图提供相同节点与选项去向，窄屏可以只在图容器内横向滚动。节点位置是自动投影，不写入内容包，不代表玩家存档分支。

本地诊断会指出缺失起点、悬空目标、重复节点或边、未连接节点、循环、缺少结局、选项与边不一致，以及原有内容校验和组局候选缺口。有节点定位信息的诊断可直接定位该节点。即使图中存在循环或悬空边，投影也会有限返回，保留可修复的视图。

“未发现剧情图结构问题”只表示本地预检没有发现这些问题。它不替代服务端自动检查、内容审核或实际资源门禁，也不代表所有职业事实已核验。

## 版本与资源边界

已发布正文不能原地修改；发布新草稿只改变新开局入口。已经开始的旅程继续绑定原内容包、组局和资源版本，旧对白仍取已提交事件，不使用新标题或新规则替换历史。回退入口同样不迁移旧存档。

发布时仍检查实际图片、固定资源清单版本、文件哈希、许可、审核记录及数量要求。新增逻辑引用但缺少真实资源会阻止发布。图形编辑器没有资源上传或实时生图入口。

## 实现与验收位置

纯函数与校验位于 `packages/content/studio.ts`，界面位于 `apps/web/app/components/ContentGraphEditor.vue`，工作台集成位于 `apps/web/app/pages/admin.vue`。保存、检查、审核、发布继续调用 `POST /api/admin/content`，详见 [API 契约](api.md)。

`tests/studio.test.ts` 覆盖稳定布局、合流、异常图有限返回、草稿边界、字段与资源同步、不可变输入及非法规则修改；本轮已运行的领域验证见交付汇总。`tests/e2e/studio.spec.ts` 为浏览器流程用例，是否实际通过以[验收记录](verification.md)为准，本文不据测试文件存在宣称浏览器通过。

新增/删除节点、拖拽、批量导入、独立子图预览和多人协作仍是后续工作，详见[路线图](roadmap.md)。
